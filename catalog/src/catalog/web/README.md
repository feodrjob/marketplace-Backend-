# Web слой модуля catalog

REST-контроллеры, DTO запросов/ответов, валидаторы и мапперы web-слоя каталога и поиска товаров.

## Публичные маршруты

Все маршруты доступны без JWT.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/v1/catalog/products | Поиск и страница товаров |
| GET | /api/v1/catalog/products/{id} | Карточка доступного товара |
| GET | /api/v1/catalog/categories | Дерево или плоский список категорий |

Список принимает `q`, `sort=price,asc|price,desc|createdAt,asc|createdAt,desc`, `page` и `size`.
Страницы считаются с нуля, по умолчанию `page=0&size=20`.
Максимальный размер страницы — 100, правая граница страницы — не более 10000 результатов Elasticsearch.

Фильтры: `f[price]=min,max`, `f[category]=slug1,slug2`, `f[categoryId]=uuid1,uuid2`, `f[sellerId]=uuid1,uuid2`.
Границы цены включены. Для категорий и продавцов поддерживается отрицание: `f[sellerId]!=uuid`.
В URL имя такого параметра — `f[sellerId]!`, символ `=` отделяет значение.
Отрицание диапазона цены не поддерживается.
Повтор одного параметра, неизвестный параметр, неверное поле сортировки или значение фильтра возвращают 400.
Несколько значений фильтра передаются через запятую.

Ответ страницы: `items`, `page`, `size`, `total`.
`total` — число совпадений в поисковом индексе, а не число элементов страницы.
Без `q` и `sort` товары идут по дате от новых к старым; с `q` — по релевантности.
При равенстве основного ключа порядок стабилизируется идентификатором товара.

Категории принимают `tree=true|false` (по умолчанию true) и необязательный `parentId`.
Сам родитель в поддерево ответа не включается.
Неизвестный или недоступный родитель возвращает 404.
Скрытые, архивные товары и товары из неактивной ветки категорий не выдаются, даже если индекс устарел.

Ошибки параметров возвращаются как `application/problem+json` с полями
`type`, `title`, `status`, `detail`, `instance`, `timestamp`.
Недоступность поискового хранилища или Auth возвращает 503.

## Связь слоёв

Поиск, фильтрация, сортировка и пагинация выполняются в Elasticsearch.
Карточки и изображения читаются из PostgreSQL с сохранением порядка поисковой выдачи.
Название и описание магазина получаются из Auth через публичный `GET /api/v1/sellers/{id}/shop`,
где `id` — идентификатор аккаунта продавца.
В одной странице данные каждого магазина запрашиваются один раз.
Отсутствующий продавец оставляет поля магазина пустыми; сетевой сбой Auth возвращает 503.

`CATALOG_AUTH_BASE_URL` задаёт адрес Auth, по умолчанию `http://localhost:8081`.
В Docker Compose используется `http://auth:8081`.

При запуске каталог загружает товары из PostgreSQL в Elasticsearch порциями по 500 записей.
`CATALOG_SEARCH_INITIALIZE_ON_STARTUP=false` отключает эту загрузку.
Она обновляет существующие документы и добавляет новые, но не удаляет документы отсутствующих товаров.
Синхронизация изменения и удаления товаров во время работы должна подключаться к будущим сценариям управления ассортиментом.
При устаревшем индексе страница может содержать меньше элементов, а `total` может включать уже недоступные товары.

## Проверка

Для интеграционных тестов нужен запущенный Docker.

~~~powershell
.\gradlew.bat :catalog:test :auth:test
~~~

Ручные запросы к локальному каталогу:

~~~powershell
curl.exe --globoff "http://localhost:8083/api/v1/catalog/products?q=книги&f[price]=10,50&sort=price,asc&page=0&size=1"
curl.exe --globoff "http://localhost:8083/api/v1/catalog/products?f[category]=books,auto"
curl.exe --globoff "http://localhost:8083/api/v1/catalog/products?f[price]=50,10"
curl.exe "http://localhost:8083/api/v1/catalog/products?page=0&page=1"
curl.exe "http://localhost:8083/api/v1/catalog/categories?tree=false"
~~~

Первые два запроса должны вернуть 200, некорректный диапазон и повтор страницы — 400.
Проверять список нужно на товарах, которые присутствуют и в PostgreSQL, и в поисковом индексе.

Сохранённый YAML: `catalog/resources/static/openapi/catalog.yaml`, доступен по `/openapi/catalog.yaml`.
Порядок обновления и проверки описан в `docs/catalog-api.md`.
